# 人才线索工作台

从技术招聘实习场景出发，将论文寻访、人员核验、应聘跟进与招聘分析串成一套可以操作的数据工作流。作者：陈嘉晨。

**[在线体验](https://talent-workbench-chenjc.craftydell20.chatgpt.site/)** · [演示路线](DEMO_GUIDE.md) · [Mapping 说明](MAPPING.md) · [R 分析讲解](analysis/作品讲解.md)

## 业务问题与实现

| 业务问题 | 工作台实现 |
| --- | --- |
| 论文和研究者信息分散，寻访关系难以整理 | 查询 OpenAlex / Crossref，提取作者、署名机构和共同作者，保留来源 |
| 同一人多岗应聘，阶段和历史容易混淆 | 人员、岗位申请、阶段事件分开建模；同人同岗更新进展，不重复创建申请 |
| 只看到招聘总数，难以追踪具体人选 | 按岗位和观察期查看阶段转化，下钻人选，导出包含面试官与评价的 Excel |
| 导入数据存在缺失、重复或日期问题 | 使用当前记录、上传 CSV 或载入 120 条检查练习数据，复核问题行后导出 |
| 模型效果缺少可复核依据 | 用公开月度数据运行 R 时间留出实验，比较模型与简单基线 |

## 快速运行

无需安装前端依赖或执行构建。安装 Node.js 后，在项目根目录运行：

```sh
node serve.cjs
```

浏览器打开 `http://127.0.0.1:8787/`。也可使用其他静态 HTTP 服务；不要直接双击 HTML，以免影响文档解析和模块加载。

## 建议体验顺序

1. **招聘分析**：选择岗位和日期范围，查看阶段人数、相邻转化率，点击阶段查看人选，导出 Excel。
2. **岗位与应聘**：按岗位和当前阶段筛选，选择应聘者，查看跟进记录并更新进展。
3. **人才 Mapping**：输入论文 DOI / 标题，或上传 PDF / DOCX，确认文章后提取作者；也可输入研究者姓名或 ORCID，查看文章和共同作者。核对后保存线索，按需关联岗位。
4. **人才线索 / 内部人才库**：查看来源、核验信息和当前浏览器内的历史档案。
5. **数据处理**：载入 120 条练习数据，查看问题行、修改并重新检查，导出通过记录。
6. 从 **项目说明** 进入预测验证，查看公开数据、时间划分和模型比较结果。

## 数据口径

- **人员与应聘分开**：`personId` 标识人员，`applicationId` 标识一次岗位申请。同人不同岗位分别记录；同一岗位以最新阶段展示。
- **阶段由事件推导**：备注、安排面试、补充反馈不会自动推进阶段；新增阶段需人工确认。
- **漏斗是累计到达人数**：按观察期内首次入池的申请统计，截至结束日期到达各阶段的人数。到达后续阶段的人也计入前序阶段；阶段完成不等于面试通过。
- **名单按最新进展分组**：Excel 阶段明细中，一条申请只归属一个最新阶段，前序面试评价仍保留在该行；完整事件另列工作表。
- **相邻转化率**：本阶段累计人数 / 上阶段累计人数；零分母留空。阶段差额包含等待与结束，不能直接解释为流失或因果影响。

## 数据来源与边界

**预置招聘数据**用于演示流程，不是快手真实候选人、面试评价或招聘业绩。显示姓名取自用户提供的公开作者名单，不能据此认定为对应作者的真实学历、任职或应聘经历。寻访来源类型为演示分配。14 个岗位整理自 2026-10-28 快手官网公开社招列表，见 [岗位来源](岗位整理说明.md)，不代表作者实际负责这 14 个岗位。

**Mapping 会发送真实网络查询**，数据来自 OpenAlex / Crossref。未接入企业 ATS、GitHub 关系图或自动联系方式搜集。学术库可能有收录延迟、同名和机构信息缺失；署名机构不保证当前任职。部分网页因跨站限制无法读取，可改用标题、DOI 或文档。扫描件没有 OCR，旧版 `.doc` 需转换为 `.docx`。

**公开分析数据**来自 BLS 经 FRED 发布的 JTSJOL，共 309 个月，2000-12 至 2026-08；见 [来源与校验信息](public-data/SOURCE.md)。它用于独立展示分析方法，不能替代内部招聘数据或直接代表国内 AI 招聘需求。

## R 实验复现

使用 base R，按时间划分训练集 178 个月、验证集 59 个月、测试集 60 个月。比较 AR(1)、AR(3)、AR(12) 和上月值基线，以验证集 MAE 选型，再在测试集评估。结果保留上月值基线，测试 MAE 314.4 千个、RMSE 402.2 千个，没有为了展示复杂模型而声称有额外增益。

```sh
Rscript analysis/market-analysis.R
node verify-market.cjs
```

这是使用最新修订数据的一步预测历史留出实验，并未还原历史发布版本或实时可用信息集。输出表、运行日志和网页读取的结果快照均在 `analysis/`。

## 技术结构与检查

原生 HTML / CSS / JavaScript，无应用后端。`workflow-core.js` 为纯计算模块，`workflow.js` 负责交互和浏览器存储；`mapping-core.js` 处理学术元数据；`export-data.js` 与 `analytics-export.js` 生成明细工作簿。PDF.js、Mammoth 和 ExcelJS 位于 `vendor/`，随附各自许可证。

```sh
node test-workflow.cjs
node test-export.cjs
node test-data.cjs
node test-analytics.cjs
node test-mapping.cjs
node verify-market.cjs
```

检查覆盖同岗去重、跨岗关联、阶段规则、观察截止日、最新阶段唯一归属、数据清洗、元数据解析和公开分析结果。`test-data.cjs` 中旧文本分类器的固定开发样例分数不是业务准确率，也不是独立泛化评估。

## 存储与接口

- 工作区保存在使用者自己的浏览器 `localStorage` 中，不会跨设备或多人自动同步。数据处理中的完整 JSON 导出可用于留存备份；当前没有一键恢复功能。
- PDF / DOCX 在浏览器内解析，仅将确认的标题、DOI 或研究者标识发送给学术接口。
- 没有接入付费大模型 API，没有内置共享密钥。使用者可在页面自行输入 OpenAlex Key，仅供当前页面请求使用，请勿把个人密钥写进公开代码。
- 本项目是作品原型，没有企业权限隔离和审计机制，请勿导入未获授权的真实招聘资料。原始实习文档、私人简历及本机运行数据不在此仓库中。

界面设计参考 Impeccable、Vercel Web Interface Guidelines 与 shadcn-admin 的公开思路，未复制其项目代码。
